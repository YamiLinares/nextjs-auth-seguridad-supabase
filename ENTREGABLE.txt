ENTREGABLE
==========

Actividad: Implementar capas de seguridad a nivel de servidor y estrategias de
posicionamiento orgánico para aplicaciones web profesionales.
Práctica: Seguridad de autenticación con cookies httpOnly en Next.js.

Proyecto: SecureGate (nextjs-auth-seguridad-supabase)
Autora: YamiLinares

Repositorio GitHub (público): https://github.com/YamiLinares/nextjs-auth-seguridad-supabase
Sitio en producción (Vercel): https://nextjs-auth-seguridad-supabase.vercel.app

DESCRIPCIÓN
Aplicación de autenticación con Next.js 16 (App Router) y Supabase Auth. La
sesión se guarda en cookies httpOnly que JavaScript no puede leer; toda la
autenticación pasa por Server Actions y cada acceso a datos privados se
verifica en el servidor.

FUNCIONALIDADES
- Registro con validación en el servidor y confirmación de email.
- Inicio de sesión con email y contraseña, y redirección al panel.
- Cierre de sesión (este dispositivo o todos) mediante Server Action.
- Recuperación de contraseña por correo y página para definir una nueva.
- Manejo de enlaces inválidos o caducados.
- Panel privado con los datos del usuario y un perfil editable (tabla con RLS).
- Navegación que cambia según la sesión; páginas 404 y de error.
- Diseño responsive y accesible.

TECNOLOGÍAS
Next.js 16.4.3, React 19.3, TypeScript 5.9 (strict), @supabase/ssr 0.12.7,
@supabase/supabase-js 2.118, Zod 4.6, Tailwind CSS 4.3, Vitest 5, Vercel.

MEDIDAS DE SEGURIDAD
- Cookies de sesión: HttpOnly, Secure en producción, SameSite=Lax, Path=/ y
  7 días de duración. La sesión se renueva y los tokens rotan.
- Verificación en el servidor con getUser() antes de entregar datos privados;
  una sesión cerrada no da acceso aunque se reutilicen sus cookies.
- proxy.ts: rechaza peticiones mutables de otro origen (CSRF), genera la CSP
  con nonce, renueva la sesión y protege /dashboard.
- Server Actions: validación con Zod, sin tokens ni contraseñas en las
  respuestas o en los logs, y mensajes que no revelan si una cuenta existe.
- Redirecciones limitadas a rutas internas (sin redirecciones abiertas).
- XSS: React escapa el contenido; CSP con nonce y 'strict-dynamic'; ningún
  token en localStorage ni sessionStorage.
- Cabeceras: CSP, HSTS, X-Frame-Options, X-Content-Type-Options,
  Referrer-Policy, Permissions-Policy y Cross-Origin-Opener-Policy.
- Base de datos: Row Level Security, cada usuario solo accede a su perfil.
- Respuestas privadas con Cache-Control: no-store.

SEO TÉCNICO
Metadatos title y description, Open Graph, lang="es", robots.txt,
sitemap.xml (solo la página pública), noindex en las páginas de autenticación
y privadas, URL canónica en producción e icono de la aplicación.

git clone https://github.com/YamiLinares/nextjs-auth-seguridad-supabase.git
cd nextjs-auth-seguridad-supabase
npm install
Copy-Item .env.example .env.local   (y completar las variables)

LIMITACIONES
- El correo integrado de Supabase permite pocos envíos por hora; para uso
  real se necesita SMTP propio.
- Con las plantillas de email por defecto, el enlace debe abrirse en el
  mismo navegador donde se inició el registro o la recuperación.
- Un token de acceso sigue siendo válido criptográficamente hasta su
  caducidad (1 h); por eso los datos privados se protegen con getUser().
- Las medidas SEO mejoran la base técnica, pero no garantizan posiciones.
